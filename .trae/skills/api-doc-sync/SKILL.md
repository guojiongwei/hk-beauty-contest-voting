# API 文档同步规范

## 触发条件

- 新增或删除路由
- 修改请求参数、响应字段、状态码
- 调整认证要求（是否必须携带 JWT）
- 修改错误提示文案

## 文档结构

每个接口必须包含：

1. 接口名称
2. `### URL`：请求方法与路径
3. `### 认证`：是否需要 `Authorization: Bearer <token>`
4. `### Request 示例`：JSON 代码块
5. `### Response 示例`：成功与失败各一组 JSON 代码块
6. `### 说明`：关键业务规则（如重复投票限制）

## 一致性检查

- 路径与 `config/routes.rb` 完全一致
- 字段名与控制器 `permit` / 渲染字段完全一致
- 状态码与控制器 `status:` 完全一致
- 错误文案与模型校验 `message` 完全一致

## 状态码约定

| 场景 | 状态码 |
| --- | --- |
| 查询成功、登录成功、登出成功 | 200 |
| 注册成功、投票成功 | 201 |
| 未登录、Token 失效 | 401 |
| 资源不存在 | 404 |
| 参数错误、重复投票 | 422 |
| 服务端异常 | 500 |

## 检查清单

- [ ] 6 个核心接口均有示例
- [ ] 成功与失败示例均存在
- [ ] Request 示例字段可直接复制调用
- [ ] 文档中没有占位符或未实现字段
